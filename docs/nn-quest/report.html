Quantik · measured against a perfect solver

The ply-four gap

Quantik is small enough to solve exactly, so a search engine plays the endgame perfectly. It plays the opening at 84.8 %. That gap is the whole reason a neural network can beat it — and it does, on less time per move.

the game

Sixteen squares, four shapes

Quantik is played on a 4×4 board with four piece shapes in two colours. You win by completing any row, column, or 2×2 zone containing all four different shapes — colour is irrelevant, so you can win with your opponent’s pieces. The catch: you may not place a shape where the opponent already has that same shape in the row, column, or zone. A player with no legal move loses.

the problem

You cannot out-search a solved game

The existing engine, MinimaxEngine, runs alpha-beta to depth 16 with a transposition table. No Quantik game exceeds 16 plies, so given enough time it does not approximate anything — it solves. Beating it outright is impossible; the only meaningful contest is at a fixed budget.

So the first thing built here was not a network. It was a ruler: 640 positions solved to game-theoretic truth by an exact oracle, held out from all training, scoring each engine on a single question — given a position you can provably win, do you play a move that keeps the win?

Accuracy tells you where an engine is wrong. A win rate only tells you that it lost.

The ruler said something that redirected the entire project.

the finding

Minimax is perfect — from ply 8 onward

Past the halfway mark, minimax at 100 ms plays every won position correctly. It never errs again. But at ply 4, with twelve squares still empty, it converts only 84.8 % of wins. The search cannot reach the end of the game in the time it has.

This made the goal precise: match minimax in the endgame, beat it at plies 4–7. Work spent making the network stronger at ply 10 would have been wasted.

the method

Distil the solver, don’t imitate the player

A from-scratch AlphaZero run was the first attempt. It reached 97.2 % accuracy — exactly level with minimax — and stopped improving. The probe explained why: its value head had a mean error of 0.727 against a ±1 truth. It was outputting nearly zero. It did not know who was winning.

That failure is structural, not a bug. The value target was a blend of the final game result — one bit at the end of an eight-ply game — and the search’s own backed-up estimate, produced by the same untrained network. The signal was circular. Breaking that circle meant getting labels from outside.

  1. Make the rules fast enough to matter. The reference engine generated 21.6k positions/s while the network could evaluate 630k/s — self-play was 97 % rule-bound. Re-expressed as array operations over batches of bitboards: 8.1M/s, a 377× speedup, cross-checked against the reference on 3,000 positions.
  2. Solve positions exactly, in bulk. A Rust exporter turns the depth-16 solver into a labelling tool. Solving one position also solves all its children, so each solve yields an optimal-move set plus a dozen free exact values.
  3. Train on truth, not on itself. 3.09M exactly-labelled positions, 250k with exact optimal-move sets. Quantik is invariant under 192 symmetries, so every batch is replayed under a fresh random one. Training draws are balanced across plies, because the corpus is 75 % endgame and the match is decided in the opening.
  4. Search on the same clock. The network drives a batched MCTS with a wall-clock budget, on one CPU thread — the same hardware the classical engines get. Every time in this report is measured, never nominal.

Value-head error against exact truth: 0.727 → 0.084. Everything else followed from that one number.

the result

It wins, and it wins on less time

The second bar is the one that settles it. At a 63 ms budget against minimax’s 203 ms — 3.2× less thinking time on the same single thread — the network still wins 55.8% of 1,200 games. It is not out-searching the solver. It is out-knowing it.

coverage

It saw 5% of the game, and none of where it wins

power

Is the evaluation big enough?

The first draft of this report leaned on 640 solved positions. That was too few where it counted: only 33 provably-won positions at each of plies 4 and 5. The probe is now 8,440 positions, with 1,240 at each of those plies.

Both agents see identical positions, so the comparison is paired — an unpaired interval would throw away most of the evidence. On the 7,030 won positions the two disagree 259 times, and 239 of those go the network’s way. An exact paired test puts that at p = 8e-49.

Every disagreement between them is in the opening. Across 2,880 won positions at plies 8–12, neither engine makes a single mistake.

The original 640 was underpowered, not wrong. Minimax measured 84.8% at ply 4 on 33 positions and 84.4% on 951; the network 97.0% and 96.4%. The point estimates held; the intervals were simply too wide to lean on. Headline accuracies moved (network 99.6% → 99.0%) because the new probe deliberately weights the opening far more heavily — not because any agent changed.

the honest part

What this is not

  • The network did not learn Quantik from nothing. It was taught by an exact solver. The from-scratch AlphaZero run is in the table precisely so the comparison stays honest — and it lost.
  • The ceiling here is low by construction. In side-balanced pairs, two near-perfect players each win the side they were handed, so scores are pulled toward 50 %. Clearing it by ten points means the opening error rate is genuinely near zero, but nobody is winning 90 % of these games.
  • A three-hour solve was thrown away. The oracle buffered its results and wrote them at the end; an over-broad process kill destroyed the lot. It now streams and resumes — which immediately saved the next interrupted run. A job measured in hours has to be interruptible by construction.
  • Sixteen probe positions leaked into training. The corpus builder filtered the positions it sampled but not the child rows derived from them, so 16 of the original 640 arrived as value-only rows at plies 7-9 — none with a move label, none at plies 4-6. Worst case it moves the network 99.63% → 99.61% and minimax 97.19% → 97.11%. Immaterial, but the filter now sits where it cannot be bypassed, and the 7,800-position probe excludes the corpus up to symmetry.
  • One reported metric was wrong for an afternoon. Validation averaged unequally-weighted chunks, printing a real 89 % top-1 accuracy as 11 %. It looked plausible — a low loss beside a low accuracy — which is exactly what made it dangerous.
